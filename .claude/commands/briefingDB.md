# BriefingDB

1. Read priorities and exclude archived work.
2. Read recent activity and active project pages.
3. Retrieve only recent facts/scenes that materially update those pages.
4. Include a calendar section only if the user configured a calendar connector.
5. Produce: schedule, active threads, priority reminders, contradictions or
   stale-state warnings, and three to five concrete next actions.
6. Do not invent a deadline, calendar event, project status, or blocker.
7. Log that a briefing was generated without claiming it changed project state.
